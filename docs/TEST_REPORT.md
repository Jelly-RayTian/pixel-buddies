## 发现并修复的问题

1. **每日挑战相邻两天可能撞图**：原方案是“与昨天相同就顺延一张”，测试发现 2026-02-20 与次日都是“温馨卧室”（顺延后的结果可能与下一天的原始结果相同）。改为“每 12 天一轮的确定性洗牌，并修正轮次衔接处”，365 天测试通过。
2. **每日页午夜刷新可能无限递归**（代码审查发现）：倒计时到 0 秒时调用 `onEnter()`，而 `onEnter()` 又会立即再次检查同一秒。改为比较日期键，日期变化时只刷新一次。
3. **背景音乐与音效共用一个节点挂两个 AudioSource**：改为分别挂在子节点上，避免同类组件冲突。
4. **3.8.0 / 3.8.1 没有 `Label.enableOutline`**：Logo 白字会失去描边、在浅色背景上看不清。增加 `LabelOutline` 兼容分支。
5. **旧版微信基础库可能没有 `globalThis`**：平台对象获取增加 `typeof wx` 与 `GameGlobal` 兜底。
6. 星级测试的期望值写错（26 步正好等于两星线），已修正测试。
7. （实机）首页在高屏手机上“开始拼图”下方空白过大：改为按可用高度分配各段间距。
8. （实机）“拼图”图标渲染后像一团色块：重画为 2×2 方块图标。
9. （实机）结算页“新作品收藏”徽章压住副标题；高屏下内容偏上：调整徽章位置，内容整体居中，作品放大。

11. （实机）设置页说明文字没有顶部对齐。

主题曲原来是远程分包（约 28MB，需要已备案域名）。先试过把 2:41 的曲子压成 16kbps，听感太糊，放弃；改为用生成器重新生成 36 首更短的版本（每首约 62～87 秒，保持原速，仍是 44.1kHz 单声道 40kbps，音质编码与原来一致），合计约 12.9MB，5 个主题曲分包改为本地小游戏分包随包发布。发布检查只在存在远程分包时才要求远程域名，所以提审只缺 AppID。隐私政策里的开发者名称已填“果冻、电子大米（两位开发者）”，联系邮箱已填。

**已验证**
- 单元测试全部通过；包体测试检查所有音乐都是本地分包且合计小于 16MB；发布检查新增 2 个测试（只填 AppID 也通过、有远程分包时仍会拦 vercel.app）。严格类型检查与微信 API 兼容检查通过。
- 微信、抖音构建成功，没有 `remote/` 目录，`game.json` 列出 6 个分包；整包大小见下方构建记录。
- 36 首新曲的采样峰值都不超过 -0.8 dBFS（没有削波），响度对齐到约 -16 LUFS。

**未验证**
- 新曲的实际听感没有人耳试听过（只有用户本人试听了压缩版并认为太糊，新版是重新生成而不是压缩）；循环衔接处是否自然（生成器按无缝循环设计，但缩短后的乐段衔接没有逐首听）；缩短后每首的结构变简单（2～4 个乐段）。
- 微信开发者工具的“代码包大小”提示和真机；整包上限各处资料不一（20/30MB），约 18MB 对这两个都有余量。
